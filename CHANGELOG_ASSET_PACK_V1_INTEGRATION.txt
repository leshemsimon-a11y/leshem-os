LESHEM.S OS — Starter Asset Pack v1 (First 20) — Design Studio Integration
=============================================================================

Root-ready bundle. Upload the CONTENTS of this folder to GitHub at the same
paths. Additive, visual-only integration on top of Clean 5D-R3 — no business
logic changed, no new dependencies, no Airtable/schema changes.


WHAT THIS DOES
-----------------
Wires the uploaded 20-asset starter pack into the Design Studio, following
your stated priority order:

  1. Design Studio selected-stones strip   → DONE (fallback demo thumbnail)
  2. Empty / start state                   → DONE (real hero illustration)
  3. Concept / canvas placeholders          → DONE (preview + blueprint panes)
  4. Material swatches                      → DEFERRED (assets staged, not
                                               wired — no swatch UI exists in
                                               the files this milestone owns)
  5. Render brief preview placeholders       → DEFERRED (assets staged, not
                                               wired — DesignOutputPanel is
                                               out of scope for this pass)

Per your instruction ("if you need to defer wider use, just add the assets
and use them in the Design Studio first"), items 4–5 were intentionally NOT
wired into any UI this pass — wiring them would require touching
DesignOutputPanel / a new material-swatch picker, which are outside the
files this milestone is scoped to. The files are staged and registered in
lib/studio/assetPack.js, ready for a future explicitly-scoped milestone.


ASSET PREP (why the files differ from your upload)
------------------------------------------------------
All 20 source PNGs were 1024×1024 (~400–650KB each, ~10.7MB total) with a
thin 8–10px contact-sheet border artifact on every image. For web use I:
  • cropped the border artifact (10px each side)
  • resized per intended display context:
      - stone thumbnails (01_stones/**)              → 240×240
      - jewelry preview placeholders (02_...)         → 480×480
      - metal swatches (03_materials/metal_swatches)  → 160×160
      - empty-state illustration (05_empty_states)    → 640×640
      - blueprint (06_blueprints)                     → 640×640
  • re-saved as optimized PNG (no format change, no new dependency — Pillow
    was used only in this offline sandbox to prepare the static files;
    nothing in the shipped app performs image processing)

Total footprint: 10.7MB → 2.5MB (20 files). Filenames and subfolder
structure are UNCHANGED from your upload — same names, same relative paths
under public/assets/leshems/starter-pack-v1/ — so future asset-pack batches
can drop into the same structure without renaming anything already wired.

The manifest (asset_manifest.csv) and usage notes (asset_usage_notes.txt)
are copied alongside the assets under 08_manifest/ for provenance.

FILES CHANGED
-----------------
  components/studio/design/shell/StudioCanvas.js
    • Hero (State A): the ring-silhouette icon is replaced by the real
      "empty_studio_start_stones_to_jewelry" illustration inside a soft
      ivory frame — a genuine visual upgrade for the very first thing a
      jeweler sees.
    • Selected split (State D): the preview pane now shows the
      "jewel_ring_solitaire" preview photo (a single calm default — mapping
      a specific concept to one of the 5 jewelry images would need a
      canonical product-type field not available in this bundle, so this is
      intentionally a generic placeholder, consistent with the existing
      "תצוגת הדמיה — שלב עתידי" wording that already tells the user this is
      not final). The blueprint pane now shows the real
      "blueprint_ring_solitaire_top_side_light" technical illustration in
      place of the inline SVG sketch.
    • Every new image has an automatic fallback: if a static asset ever
      fails to load (404, deploy hiccup), the component silently reverts to
      the original inline SVG placeholder from 5D-R3 — the canvas can never
      show a broken image icon or go blank.
    • Starter (State B) was left UNCHANGED — not in your priority list for
      this pass, and changing it wasn't needed to hit priorities 1–3.

  components/studio/design/shell/StudioStoneStrip.js
    • When a tray item has a real snapshot.primaryImage, nothing changes —
      the real photo is always shown, exactly as in 5D-R2/5D-R3.
    • When a tray item has NO real image (the common case for demo/empty
      inventories), the chip now shows a best-effort matching demo stone
      photo from the asset pack (matched against the same Hebrew
      shapeHe/stoneTypeHe text already used elsewhere for the chip title —
      no new/internal fields read, nothing written back). A small gold dot
      marks it "אילוסטרציה" (illustration) via title/aria-label, so it is
      never mistaken for a real item photo, per your instruction that these
      assets are demo-only. If no keyword matches, the original generic
      line-icon fallback is used exactly as before — zero regression.

  lib/studio/labels.js
    • ONE additive key: `demoThumbBadge: 'אילוסטרציה'`. No existing keys
      touched, removed, or renamed.
